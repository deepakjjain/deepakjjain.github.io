Platform Engineer

Observability-as-Code Platform

Terraform-driven New Relic monitoring platform managing ~400 synthetic monitors via CSV config and GitHub Actions — no UI clicks, full audit trail, 2 hours per monitor cut to 15 minutes.

TerraformGitHub ActionsNew RelicDockerKubernetesAWS EKSPythonShell

Challenge

400 synthetic monitors managed through the New Relic UI. No version history. No peer review. Adding a monitor took 2 hours and required direct UI access and tribal knowledge. Scripts couldn’t be tested before deployment — failures were silent until something broke in production.

The goal: treat observability configuration the same way as application code.

Architecture

CSV as the config interface. Engineers define monitors in CSV — one row per monitor. Fields cover URL, type, frequency, alert thresholds, tags, and credential references. Terraform runs underneath. Contributors never see HCL. This lowered the barrier enough that QA leads and product engineers started submitting PRs to add their own monitoring coverage.

Six Terraform modules. One per monitor type: Ping, Simple Browser, Scripted Browser, Scripted API, SSL certificate, and Lighthouse performance. Each module translates a CSV row into New Relic resources.

Local runtime emulation via Docker. New Relic’s synthetic runtime is containerised. Running the same image locally lets engineers debug scripts before committing — catches most errors before the pipeline runs.

Private locations on AWS EKS. Two synthetic minion deployments — Dublin and Washington DC — monitor internal APIs, VPN-gated services, and region-specific latency baselines that public locations cannot reach.

Remote Terraform state with locking. Eliminates concurrent-apply conflicts across the team.

Semantic versioning with automated changelogs. Every merge triggers a version bump. Every change is traceable to a version, a PR, and a Jira ticket — a compliance requirement the manual UI approach could never meet.

What I Built

  • Three-stage GitHub Actions pipeline: validate (lint, Terraform validate, CSV checks, Jira ticket enforcement) → plan (Terraform diff posted to PR) → deploy (apply on merge, tag release, update changelog)
  • CSV validation step before Terraform runs — a wrong field returns a readable error in seconds, not a Terraform stack trace minutes later
  • Scheduled job to detect when private minion Kubernetes deployments fall behind the latest New Relic runtime and raise an automated update PR
  • Remote state backend with locking

Results

  • Time to add a monitor: ~2 hours → under 15 minutes
  • Silent failures: pipeline caught script errors before production on dozens of occasions
  • Scale: proof of concept → ~400 monitors across 6 types and 2 private locations over 3 years
  • Reliability: 300+ releases, zero pipeline-caused outages
  • Compliance: every change version-controlled, peer-reviewed, and linked to a Jira ticket
  • Impact: several production incidents detected by private location alerts before any real-user impact was measurable
