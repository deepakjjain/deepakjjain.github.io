Platform Engineer

Enterprise HR Chatbot on AWS Bedrock

RAG-based Microsoft Teams bot serving 30+ countries — container Lambda, nightly Fargate indexer, Bedrock Knowledge Base on OpenSearch Serverless, and end-to-end IaC across two independently deployed services.

PythonAWS BedrockLambdaECS FargateOpenSearch ServerlessDynamoDBAPI GatewayStep FunctionsEventBridgeTerraformGitHub ActionsMicrosoft Teams

Challenge

HR documentation at a global organisation means 30+ sets of country-specific policies, leave processes, and forms. All of it was in SharePoint. Getting the right answer meant knowing the folder structure or emailing HR directly — a slow, high-friction process at scale.

The question: could employees get accurate, location-aware HR answers from Microsoft Teams without HR involvement?

Architecture

Two independent services. A bot handles incoming Teams messages. A separate indexer keeps the knowledge base current. Different workloads — different compute. Container Lambda for the bursty, latency-sensitive bot. Fargate for the sustained, scheduled indexer.

RAG pipeline in Lambda. Each Teams webhook triggers a Python Lambda (2 GB, 900-second timeout). The pipeline rephrases the query into multiple variants using Claude Sonnet 4.5, runs parallel Bedrock Knowledge Base retrievals across all variants, scores results by document hierarchy depth and region match, then generates a grounded response with inline SharePoint links.

Bedrock Knowledge Base on OpenSearch Serverless. Documents are embedded with Titan Embed Text v2 (1024 dimensions) using hierarchical chunking — 1500-token parent chunks with 1000-token child chunks and 200-token overlap. Each chunk carries XML metadata (region, folder path, file name) embedded inline, enabling retrieval-time ranking without a separate metadata store.

Nightly Fargate indexer. EventBridge cron at midnight UTC fires a Step Functions state machine. Step Functions runs a Fargate task that authenticates to SharePoint via MSAL, extracts files by region folder, and ingests them into the Bedrock data source. Five retries at 60-second intervals at the orchestration layer — zero retry logic in application code.

Non-proxy API Gateway integration. A custom Velocity mapping template forwards the raw body and all HTTP headers to Lambda, allowing Teams handshake validation (X-Forwarded-Port, Authorization) without exposing auth headers as Lambda event top-level fields.

What I Built

  • Full Terraform infrastructure for both services — two independent root modules (bot and index) deployed to stage and prod environments
  • Container Lambda with non-root runtime user (UID 1001), IMDSv2 enforced, IAM policies scoped to specific DynamoDB table, Bedrock KB, and Secrets Manager ARNs
  • OpenSearch Serverless HNSW vector index (ef_construction=512, m=16, dim=1024) with a 120-second Terraform wait on access policy propagation to handle eventual-consistency delays
  • Step Functions state machine wrapping ECS RunTask — retries, execution history, and failure alerting at zero application code cost
  • GitHub Actions pipeline: integration (MegaLinter + Terraform plan on PRs) → delivery (semantic-release) → deployment (Terraform apply on merge), with concurrency groups to cancel stale runs

Results

  • Location-aware HR answers in Microsoft Teams for employees across 30+ countries
  • Knowledge base refreshed nightly without manual intervention since launch
  • Zero bot incidents from Bedrock throttling — exponential back-off across 8 retries absorbed peak LLM load
  • Serverless bot: zero idle cost, scales to zero between messages, no infrastructure to patch
  • Separate Terraform modules: bot and indexer deploy independently, blast radius of each change contained and reviewable
