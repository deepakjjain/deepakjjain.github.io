Platform Engineer

Self-Hosted GitHub Actions Runner Fleet

AWS EC2 runner fleet with Lambda auto-scaling, four purpose-built profiles, and billing visibility tooling — zero idle cost, IAM roles replacing long-lived secrets.

TerraformAWS LambdaEC2EventBridgeGitHub ActionsPythonDockerCloudWatch

Challenge

A large multi-repository GitHub organisation running all CI/CD on GitHub-hosted runners. Three problems compounded as the estate grew.

Cost. GitHub-hosted runners bill per-minute with OS multipliers — Windows 2×, macOS 10×. No visibility into which repositories or workflows were driving the bill.

Control. Managed runners are ephemeral, shared, and opaque. Teams couldn’t pre-install tooling, control hardware specs, or guarantee network locality for jobs hitting internal AWS resources.

Security. Jobs deploying Terraform or pushing container images needed long-lived AWS credentials stored as GitHub Secrets. Runners inside the organisation’s VPC could assume IAM roles directly — eliminating static credential exposure.

Architecture

Lambda auto-scaling via EventBridge. workflow_job webhook events route through EventBridge to a Lambda that provisions runners on-demand. A second Lambda reclaims idle capacity on a cron schedule. Zero standing EC2 cost — runners exist only while jobs need them.

Four runner profiles. One Terraform module parameterised into four distinct profiles:

  • Ubuntu 22.04 — persistent, 200GB gp3, CloudWatch log streaming
  • Linux x64 — ephemeral, 15-minute scale-down
  • ARM64 — Graviton, unlimited CPU credits, native builds replacing QEMU emulation
  • Windows 2022 — 20-minute boot allowance, 5-second webhook delay

Dual instance types per profile. Every profile specifies two instance types with on-demand failover for InsufficientInstanceCapacity errors. A single instance type’s capacity constraints never block the job queue.

GitHub App over PAT. Scoped permissions, rotating keys, tied to the organisation — not an individual user account.

Multi-region without over-engineering. EU-West-1 activates with a two-line uncomment in provider.tf and a terraform apply. No module restructuring required.

What I Built

  • Full Terraform infrastructure for the runner fleet — VPC-deployed, named for cross-account visibility
  • X-Ray tracing and CloudWatch log streaming across all Lambda provisioning functions
  • Python billing tool using GitHub’s code search and Jobs API to measure self-hosted runner usage — outputs per-workflow and per-repository CSVs with usage charts
  • Managed runner billing reporter applying OS multipliers, alerting when included minutes fall below a threshold
  • Daily offline runner cleanup workflow and fleet health checks ahead of UK and US working hours

Results

  • Cost: EC2 on-demand rates only when active — zero idle cost; largest savings on workflows that previously used Windows and macOS managed runners
  • Security: Long-lived AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY secrets removed — runners assume IAM roles via instance profile
  • Visibility: First month-over-month CI spend breakdown by repository and workflow, enabling a targeted cost optimisation backlog
  • ARM64: Native Graviton builds replaced QEMU emulation — Docker build jobs that were too slow became practical
  • Reliability: Automated cleanup and daily health checks surface issues before developers encounter them
