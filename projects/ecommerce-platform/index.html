Full-Stack Developer

E-Commerce Platform

Full-stack shopping platform rebuilt from a 6-year PHP monolith — 8s page loads cut to 2.4s, 500+ concurrent users, Black Friday-ready via automated CI/CD.

ReactTypeScriptNode.jsPostgreSQLRedisStripeDocker
View Source Live Demo

Challenge

A 6-year-old PHP monolith producing 8-second average page loads, timing out at 50 concurrent users. Cart and inventory were tightly coupled — small changes were risky to deploy and required full manual testing.

The business needed to handle Black Friday traffic and allow the frontend and backend to ship independently.

Architecture

Decoupled frontend and backend. React SPA served from a CDN, Node.js REST API on separate infrastructure. Independent deployments and independent scaling.

Redis caching. Product catalogue and session data cached with a 5-minute TTL. Eliminated 80% of database reads for browse and search paths. Checkout bypasses cache and hits the database with row-level locks — inventory freshness is non-negotiable there.

PostgreSQL with pg-pool. Row-level locks during inventory deduction prevent overselling on concurrent checkout. Connection pooling keeps the database stable under load.

Stripe Checkout Sessions. PCI compliance offloaded to Stripe. Webhook handler verifies signatures before touching order state.

Docker Compose for local dev. API, PostgreSQL, and Redis all start with docker compose up. No manual setup. No environment drift.

What I Built

  • React storefront: product listing, search with debounce, cart (localStorage + server sync), multi-step checkout
  • Node.js REST API: product, cart, order, and user endpoints with JWT auth
  • Stripe integration: payment intent creation and idempotent webhook fulfillment handler
  • Admin dashboard: live inventory editor, order management, revenue charts
  • GitHub Actions CI: lint → test → Docker build → deploy on push to main

Results

  • Page load time: 8.2s → 2.4s (−70%) — LCP measured with WebPageTest
  • Concurrent users: 500+ without degradation — load tested with k6
  • Checkout conversion: +18% after reducing checkout from 5 steps to 2
  • Deployment frequency: weekly manual deploys → multiple per day via CI/CD
